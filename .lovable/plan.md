# Полное управление контентом сайта из админки

Сейчас админка редактирует часть данных (коттеджи, услуги, цены, галерея, тексты Hero, заявки, контакты), но публичная страница `src/routes/index.tsx` берёт большую часть контента из **захардкоженных констант**. Задача — сделать так, чтобы **всё видимое на сайте** редактировалось из админки.

## Что сейчас захардкожено в `index.tsx` и не редактируется

- **Беседки** (GAZEBO_ITEMS + галерея беседок + описание раздела)
- **Трансфер** (5 групп маршрутов, цены, время ожидания, галерея авто, текст-заголовок)
- **Сезонные активности** и **доп. товары** (дрова, угли, доставка) — частично в услугах, но не всё
- **Тексты разделов** (заголовки/подзаголовки Stays, Gazebos, Activities, Transfer, Request)
- **Список того, что «включено»** в бронирование
- **Пункты формы «Как забронировать»** (шаги 1-2-3)
- **Hero-изображение и логотип** (в assets)
- **Соцсети/Telegram-ссылка**, часы работы, email

## Что делаю

### 1. Расширяю доменную модель (`src/lib/api/types.ts`)

Добавляю новые ресурсы: `Gazebo`, `TransferRoute` (с полем `group`), `TransferPhoto`, `SectionText` (пары заголовок/подзаголовок для разделов), `HeroImage`. Оставляю существующие ресурсы (`Cottage`, `Service`, `PriceRow`, `GalleryImage`, `Booking`, `SiteSettings`) без ломающих изменений — только добираю поля (например, `SiteSettings.email`, `heroImage`, `bookingSteps[]`, `stayIncluded[]`, `transferWaitPrice`, `gazebosDescription`).

### 2. Расширяю mock-API (`src/lib/api/mock.ts`) и REST-клиент (`src/lib/api/client.ts`)

Для каждого нового ресурса — стандартный CRUD (`list/get/create/update/remove/reorder`), с сидированием текущих значений из `index.tsx` при первом запуске. Формат совместим с REST-контрактом в `admin.README.md` — просто добавляем новые пути (`/gazebos`, `/transfer-routes`, `/transfer-photos`, `/section-texts`).

### 3. Новые страницы админки

- `admin.gazebos.tsx` — карточки беседок (title, описание, вместимость, фото, «что включено»), drag-and-drop фото.
- `admin.transfer.tsx` — 5 групп маршрутов (В отель / Из отеля / В аэропорт / Из аэропорта / Мурманск–Териберка), редактор строк «Откуда → Куда — цена», галерея авто трансфера, стоимость часа ожидания.
- `admin.texts.tsx` — расширяю: добавляю заголовки/подзаголовки всех секций (Stays, Gazebos, Activities, Transfer, Request), шаги «Как забронировать», список «что включено в бронирование».
- `admin.settings.tsx` — добавляю email, часы работы, доп. соцсети.
- `admin.index.tsx` — добавляю плитки «Беседки» и «Трансфер».

### 4. Публичный сайт `index.tsx` читает из API

Заменяю захардкоженные массивы на данные, загружаемые из `api.*.list()` в компонентах разделов. Пока backend не подключён, `VITE_API_URL` пуст → работает localStorage-mock с автосидированием текущего контента (то есть визуально после деплоя ничего не меняется, но всё редактируемо). При наличии реального backend — включается тот же контракт.

### 5. Сидирование

При первом чтении mock-хранилище наполняется теми же значениями, что сейчас в `index.tsx` — картинки из `src/assets/gallery.json`, тексты 1-в-1. Это гарантирует, что после изменений сайт не «пустой».

## Что НЕ трогаю

- Дизайн публичной страницы, вёрстка, анимации, палитра.
- Компоненты `StayCard`, `StayModal`, `ServiceModal`, `TransferSection` — только источник данных меняется, JSX прежний.
- Логика авторизации.

  GazebosAdminPage.tsx     (карточки, аналогично StaysAdminPage)
